# Agent runtime contract

这份文件把 `README.md` 的入口规则落到执行判断。详细业务流程和写入路径仍以 `SKILL.md` 与其他 references 为准。

## 触发与首步

用户提到 OKR、Objective、KR、目标承接、目标对齐、协作关系、OKR 质量检查或保存飞书草稿时触发。首步固定为确认当前用户、租户、目标周期、目标归属、任务模式和输出用途，然后运行：

```bash
lark-cli auth status --json --verify
```

身份或周期无法核验时，先停在草稿或待确认状态。

## 输入与输出

最小输入包括周期、角色/责任范围、业务结果、已知基线、目标值或验收标准、协作者和限制条件。输出必须拆开：上下文范围、OKR 草稿、历史承接、关系与 @ 清单、质量诊断、待确认项。

关键目标值、日期、主责、对齐关系和 mention 都要标明来源。缺口写 `[待确认]`。

## 读写和降级

- 默认只读取当前用户有权访问的资料并生成草稿。
- 写入需要用户明确授权，发布动作保持关闭。
- 飞书 API、页面能力或权限不足时，沿用已获得的用户材料和可访问文档，标注未覆盖范围。
- 多个同名用户、跨租户身份、目标周期不一致或页面保存状态不清晰时，暂停该条写入。

## 验证

写入后重新读取周期详情或最终页面，核对 O/KR 数量、正文、顺序、截止日期、权重、mention、保存状态和发布按钮。任何一项读回缺失，都报告为待核验。
